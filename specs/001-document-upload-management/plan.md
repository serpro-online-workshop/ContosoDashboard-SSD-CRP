## Summary

Add secure local document upload, browsing, search, preview/download, sharing, task/project integration, notifications, and administrator activity reports. The implementation remains offline-first: Blazor Server UI calls application services, files are stored outside `wwwroot`, SQLite stores metadata, and a local ClamAV scanner must pass before a file becomes available. Storage, scanning, and document authorization are isolated behind service interfaces.

## Phase 0: Research

Research decisions and alternatives are recorded in [research.md](research.md). The selected approach is local ClamAV scanning with fail-closed behavior, generated storage keys outside `wwwroot`, an additive/idempotent SQLite schema initializer, service-layer authorization, department-based team sharing, normalized relational tags, and the existing localization resources. The host must install ClamAV before uploads are enabled; scanner absence does not prevent the rest of the application from starting.

## Phase 1: Design

- [data-model.md](data-model.md) defines Document, DocumentTag, DocumentShare, DocumentActivity, relationships, validation, and scan state.
- [contracts/documents.md](contracts/documents.md) defines in-process document/storage/scanner operations and the authorized content-streaming endpoint.
- [quickstart.md](quickstart.md) defines local prerequisites, execution commands, and manual/automated validation scenarios.
- Upload flow: validate metadata, size, extension and project/task authorization; copy to a staging file outside `wwwroot`; scan; reject and clean up unless scanner reports Clean; atomically move to generated final key; persist document metadata; compensate by deleting the file if persistence fails; record successful activity and notify eligible users.
- Read flow: evaluate authorization before returning metadata or opening content. Apply the same rule to personal/project/shared lists, search results, preview, download, task attachments, and dashboard widgets.
- Direct shares are read-only. Project membership and manager permissions are evaluated independently. Team shares use current department membership, as documented in research.
- Schema changes add document tables and indexes without dropping or recreating the existing SQLite database. Existing records remain unchanged.
- New UI strings use all four shared resource catalogs; date formatting follows the active culture.

## Implementation Strategy

1. **Foundation**: add document entities, additive schema initialization, test project, storage/scanner interfaces, and service-level authorization.
2. **P1 upload MVP**: add staged multi-file upload, validation, scanning, progress/results, personal document list, and authorized download/preview.
3. **P2 discovery**: add project views, tag/search/filter/sort, and performance checks for the specified dataset sizes.
4. **P3 management and sharing**: add metadata edits, replacement/deletion, direct and department shares, notifications, and permission tests.
5. **P4 integration and reporting**: attach documents to tasks/projects, add dashboard recent/count widgets, and administrator activity reports.
